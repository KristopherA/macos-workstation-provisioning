R01
Scope and source confidence: S,W,O,L,C | H/T
Actual coverage: partial; first-login installer and agent restored in this draft; not Mac-validated.
Code reference: launcher; preflight; firstlogin; UserSpace-preferences --firstlogin; userspace-firstlogin remains superseded inspect-only.
Observed implementation: Privileged mandatory preflight gates selected apply. Module-local apply checks exist. The firstlogin installer, when apply is authorized, installs the session bin copies, the LaunchAgent plist, and the consent record, in that order, and writes the consent record last. It runs no launchctl command and writes nothing into any user home. The agent is the installed UserSpace-preferences.txt --mode apply --firstlogin. A regular firstlogin.done marker owned by the user exits 0 with no write. At login there is no terminal, so the agent reports PENDING_CONSENT and writes nothing; the user must run the installed copy in Terminal and type APPLY. The notification shows for each first-login run that stops at PENDING_CONSENT, including that Terminal hand-run. A run without --firstlogin does not show a notification. The PENDING_CONSENT record detail ends with notify=shown (none) or notify=failed (not-found|other|timeout). A failed first-login apply writes no marker, and the next run tries again. Backups use one reused firstlogin-original folder. UserSpace-firstlogin.txt is removed from this archive. Session baseline key is now read correctly; its approved value and trusted file remain prerequisites. launchd behaviour is not validated.
Policy/manual gate: Canonical R01 source and P01-P11/D01-D34 worksheet crosswalk.
