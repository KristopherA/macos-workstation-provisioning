macOS provisioning suite - technical interface
Interface reference for the documentation of this suite. 2026-11-18 (local time).
This file is the normative interface for the suite; the documentation is written from it. The version label is WSP_SUITE_VERSION in workstationadmin-lib.txt; the archive sha256 is the identity. d18 is a text-only cleanup of d17 (no interface or behaviour change): internal build paths and role names removed from comments and text, this file renamed from its earlier name to interface-plan-for-documentation.txt, plus one new harness test T1b. d15 changes: sec 13b. d16 changes: sec 13c, 13d (reviewer S-1..S-6). d17 changes: sec 3, 5, 10, 13e (module 6, FileVault).
The documentation owner owns documentation-*.txt; the code author does not edit them.

3. Scope breakdown
  Implemented apply (gated): accounts (guided Settings flow + root-only registry; no CLI
    creation), names (COMPUTER_NAME_TEMPLATE / LOCAL_HOST_NAME_TEMPLATE with {ASSET}; typed
    NAMES), firewall global enable, ssh allowlist + service, ard specified-user allowlist,
    power display sleep (20 battery / 30 AC), updates (d10/d11, R16: six update preferences,
    sec 12; never installs or restarts), userprefs (d12/d13, R21, module 2, sec 13: the operator's per-user
    preference list for users who are NOT logged in; written as the target user) and, in the user's own
    session, UserSpace-preferences.txt (same list; apply needs USER_PREFS_CONSENT=yes AND the typed word APPLY
    on a terminal; no terminal = no apply), firstlogin (d14, module 3, sec 13a/13b: the first-login LaunchAgent installer) and
    shared (d15, module 4, sec 13b: copies operator-chosen items into /Users/Shared; needs SHARED_COPY_CONSENT=yes).
  d16: apps (module 5, sec 13c) installs from a LOCAL signed .pkg or .dmg with the APP_TEAM_IDS allowlist (S-2); it is no longer disabled.
  d17: filevault (module 6, sec 13e) enables FileVault when it is off (FILEVAULT_CONSENT=yes, FILEVAULT_KEY_DIR, its own typed APPLY;
    the operator types the password into fdesetup) and writes the NEW key to <asset-tag>-FileVault-recovery-key.txt (mode 600);
    FileVault already on: no rotation, no re-enable, "no key exported". The key writer is no longer disabled; the record
    check=key-export-automatic is gone.
  Disabled (inspect only; apply -> UNSUPPORTED check=apply-disabled): admin-session Dock/Finder writes. If the shared apply gate refuses
    first, the record is BLOCKED_POLICY apply-gate instead; either way nothing is changed.
  Unavoidable consent/manual (PENDING_CONSENT/PENDING_LOGIN, never PASS): FileVault enable when FILEVAULT_KEY_DIR and
    FILEVAULT_CONSENT are not configured (enable in Settings and save the NEW key by hand; runbook), external key import, SSH remote-user FDA and remote tests, ARD effective access, app
    sign-in/licensing/first launch, app privacy consent, visible Dock/Finder/date checks,
    restart unlock tests, HostName (never set by design).
  Restoration candidates (qualitative, each needs its own frozen snapshot, negative tests, review and independent test pass; no
  timeline implied). User preferences (module 2) is restored since d12 and hardened in d13; the remaining candidates:
    admin-session Dock/Finder - can reuse the module-2 pipeline (checked backup, typed read-back, table) inside
      workstationadmin's own session; its Dock/Finder policy keys are still to be defined by the owner. Moderate.
    FileVault key writer (module 6) - RESTORED in d17 (sec 13e); Mac adversarial tests are tracked as Mac items.
    apps pkg - RESTORED in d16 (module 5, sec 13c) for local vendor .pkg/.dmg files; App Store apps stay with MDM/
      Apps and Books or the user (R12; no Apple Account, no purchase).

4. Gates
  Root apply boundary in EVERY write module (wsp_apply_gate): Darwin; sudo from
  workstationadmin; workstationadmin is console user (checked reader, sec 9); policy TARGET_OS_MAJOR numeric and equal
  to the strict sw_vers major; ALLOWED_BUILDS lists the strict build; operator is admin; SIP
  reported enabled; MDM enrollment state readable. Any failure -> inspect only +
  BLOCKED_POLICY P01 apply-gate. Launcher apply: preflight (sudo, inspect) first; non-zero
  stops all modules. Unset operation policy blocks only that operation.

5. Policy
  /Library/Management/WorkstationProvisioning/policy.conf (root, not group/world writable,
  no ACL): TARGET_OS_MAJOR, ALLOWED_BUILDS, COMPUTER_NAME_TEMPLATE, LOCAL_HOST_NAME_TEMPLATE,
  SSH_ENABLE, APP_LIST, APP_PACKAGES, APP_TEAM_IDS, APP_SOURCE_DIR, APP_INSTALL_CONSENT (sec 13c), FILEVAULT_KEY_DIR, FILEVAULT_CONSENT (sec 13e), UPDATES_* (sec 12: five keys accept only "on", UPDATES_MACOS_INSTALL only "off"), and module keys. Read by whitelist reader, never sourced.
  Values containing ` $( ; & | < > are rejected by the reader.
  APP_LIST = Label/BundleName[/store] entries separated by ":" (example:
  "ExampleChat/ExampleChat:Example Sheets/Example Sheets/store"; the harness uses exactly
  this spelling). Label and BundleName use [A-Za-z0-9 .+-]; BundleName is the .app name
  without suffix; "/store" is the only third field and marks an App Store app.
  Unset or malformed -> the apps module is BLOCKED_POLICY (no default list), audit check
  app-list BLOCKED_POLICY "malformed". wsp_app_list REJECTS (whole value, no partial list):
    (1) any empty part: a leading, trailing or doubled ":" (so a trailing ":" is an error,
        not a silently ignored separator), an empty Label, an empty BundleName, or an empty
        third field ("A/B/");
    (2) a Label with a leading or trailing space;
    (3) a BundleName that starts with "." (hidden or path-like names);
    (4) a BundleName with a leading or trailing space;
    plus: an entry without "/", a third field other than "store", and any character outside
    [A-Za-z0-9 .+-] in Label or BundleName. A space INSIDE a name is allowed.
  /Library/Management/WorkstationProvisioning-Session/session.conf (recommended install: root, 0644, no ACL.
  The reader ENFORCES: regular non-symlink, root-owned, not group/world writable, no ACL,
  trusted ancestry; it does NOT require exactly 0644 - 0600 makes target reads fail/unset,
  never succeed; the file is read by awk, never executed. No installer is delivered):
  USERS, USER_PREFS, HOT_CORNERS_POLICY, SHARED_ITEMS, APP_LIST (same grammar as policy), TARGET_OS_MAJOR (required audit
  baseline; missing or different -> audit refuses, --allow-untested-os marks UNSUPPORTED).
  SHARED_ITEMS here is read ONLY by UserSpace-audit (read-only: is each approved item present and readable by the user). The module-4
  writer reads SHARED_ITEMS (and SHARED_SOURCE_DIR, SHARED_COPY_CONSENT) from the ROOT policy only; the session value can never change
  what is copied. Keep both lists equal. d15 draft4: the unused FIRSTLOGIN_USERS key was removed from the root policy allowlist (the
  first-login installer and agent use session USERS); a FIRSTLOGIN_USERS line is now ignored like any unknown key.
  Root-only state: asset-tag (root, 0600), accounts.list (root, 0600). No key state.

6. Trust
  Suite dir, every ancestor, library and entry: not symlink, owner root/workstationadmin,
  not group/world writable, and ACL rule: ls -ld mode "+" refuses; "@" (xattr, which hides
  "+") requires a one-line "ls -lde" listing; any listing failure refuses. Data files
  (policy, session, registry, asset tag): same, whole ancestry. Accounts registry: root-
  owned mode 600, else not consumed. Residual: an ACL the OS cannot READ may list as none;
  path checks are not pinned through use (same-trusted-actor limit).
  Report --output: any existing object at the path (any type) refuses; directory must be
  caller-owned, not group/other writable, ACL-free with trusted ancestry. Group/other READ
  on the directory is NOT rejected (a private 0700 parent is a recommended operator
  precondition; filenames/timing may be visible otherwise; content is not - files are
  created 0600 under umask 077). After open, PATHNAME checks (not descriptor identity)
  require a regular empty file; records go to the held descriptor. A same-uid/root
  replacement between check and open remains possible (bounded pilot limit).

7. Pseudonyms: one random salt per process (stdin from launcher, else generated once).
  Bootstrap (preamble, common to every entry incl. launcher and both UserSpace entries)
  unsets every inherited WSP_* name except WSP_FIXTURE_ROOT and turns allexport off, so
  the salt is not passed to child tools. Tested in fixtures for all entry types; the
  salt is pseudonym hygiene, not a secret, and no adversarial-child guarantee is made.

8. Reports (wsp-report/1)
  Header: suite, script, sha256, lib_sha256, suite_id, tz, os, build, arch, report type,
  plan_run, apply_run, evidence_mode. module-start adds policy_id (16-hex opaque hash when
  the policy file is readable and trusted, else "not-readable").
  Launcher --plan-run/--apply-run ID ([A-Za-z0-9+-], <=48) also emit type=link.
  Values classified first then whole-value redacted; random run salt via stdin.
  Production stderr: all tool stderr goes to /dev/null; only fixed suite messages (fd 5).
  Provenance: suite_id hashes the shell-file closure only, not the tar/manifest/interface;
  policy_id hashes policy.conf only (not session.conf). Keep the tar hash and a nonsecret
  policy/session revision separately. firstlogin header says report=inspect while its
  module-start shows plan (inspect normalised); neither is remediation.
  Capture (wsp_run), the one boundary for tool reads: tool stdout | head -c MAX+1 | tee
  (copy counted by wc -c) | od -Ao -v -to1. Tool stdout never reaches the capture as text.
  Fails CLOSED (WSP_RC=255, errclass=parse, empty value, WSP_CAPTURE=<reason>; the
  tool's own exit stays in WSP_TOOL_RC) unless ALL hold: C0 (d8) both internal
  substitutions (capture pipeline incl. stderr classifier; awk validator) run under
  pipefail and their exit status is checked; the validator output ends with its own
  end marker and is split by fixed offsets; escape length = 5 x byte count; exact frame; head/tee/od exit 0;
  every od address = running byte count and final address = triplet count = wc count;
  triplets 000..377; NO NUL byte anywhere (checked before decoding, for every caller);
  <= 1 MiB (WSP_CAP_MAX); decoder printf exit 0 and decoded byte length = raw length minus
  trailing LFs. Callers treat WSP_RC != 0 as not proven, so all consumers fail closed.
  Also routed through it: admin membership (dsmemberutil), secure-token status (sysadminctl, stderr folded in; conflicting status -> UNKNOWN) and
  the firstlogin plist ProgramArguments read (plutil, rc checked).
  "One line" = raw bytes: >=1 byte, one LF which is the last byte, no CR.
  Strict scalar readers are the only read path for OS version (N.N[.N]), build
  ([0-9]{2}[A-Z][0-9]{1,5}[a-z]?), architecture (arm64|x86_64) and user GUID
  ("GeneratedUID: <UUID>"): exit 0 + one line + grammar, else no value. Consumers: apply
  gate, preflight (target-os, build, architecture), audit baseline and app arch, apps arch,
  FileVault volume-owner branch, ssh/accounts GUID, report header and module-start
  os/build/arch (which print "unknown" instead of an unchecked value).
  No external text transform (awk/sed/tr/wc/grep) sits between a capture and a decision:
  module fields use in-shell helpers wsp_field (single "KEY value" line, exactly two
  fields), wsp_line_match (exactly one line with the prefix), wsp_words (whitespace
  normalise + count); globbing is off while splitting.
  Exit: 0 complete, 2 incomplete, 3 FAILED or report/forward write failure, 4 refused, 64 usage.

9. Identity and session context (d8)
  Typed readers on wsp_run (exit 0 + raw one line + account grammar
  ^[A-Za-z_][A-Za-z0-9_.-]{0,31}$, else no value): wsp_read_user (id -un),
  wsp_read_console (stat -f %Su /dev/console), wsp_read_self (real id -un; file trust).
  Fixture mode reads user/console through id_ctx/stat_ctx stubs so tests inject them;
  only the EUID/SUDO_USER parts are skipped in fixtures. Root checks use $EUID.
  wsp_context_why ROLE prints exactly "ok" or a reason; every caller requires "ok"
  (an empty or failed substitution refuses). Roles and consumers:
    operator-sudo  console = workstationadmin           apply gate (root role)
    operator-user  user = workstationadmin = console    launcher, admin-session, gate (user role)
    target-gui     user != workstationadmin, = console  UserSpace-audit, UserSpace-preferences
  Host-name redaction words are read through wsp_run (wsp_add_host_redactions).
  Account existence: wsp_user_state NAME prints yes | no | unknown, read through wsp_run
  (dscl -read UniqueID): yes = exit 0 and one numeric UniqueID line; no = dscl exit 56
  AND empty stdout AND stderr of the not-found class (eDSRecordNotFound or "No such key";
  confirm both on a Mac); anything else = unknown (D9: exit 56 alone is not enough). Operator record
  and account checks report UNKNOWN, never FAILED/"missing", when existence is not
  determinable (preflight, audit, accounts).
  Static check (workstationadmin-static-check.txt, run by the harness with --check-allow):
  after bootstrap, no native tool outside wsp_run (N), no unchecked pipeline in $(...) (P,
  "&&" is not a check), none in [ ] or case (Q); (D9, rule R; widened in d10) no pipe into
  grep, awk, sed, tr, cut, wc, sort, uniq, paste, head, tail, cat, tee, xargs, od, shasum,
  other interpreters (perl, python, ruby, jq, plutil, sh, bash, osascript ...) or other
  text tools (bc, base64, rev, column, nl, fold, xxd, dd, strings, iconv, basename ...),
  whether written bare, by absolute path, behind command/env/exec/nice/nohup/time/sudo (bare
  or by path) or after VAR=value; also no here-string, no process substitution and no pipe at
  the end of a line. A captured fact is therefore never matched by an unchecked external
  process outside $(...) either (in-shell helpers wsp_line_match, wsp_any_line, wsp_any_line_re,
  wsp_field, wsp_words, wsp_re and case/[[ =~ ]] replace them); N also covers condition, brace and negation position (if, while,
  then, do, else, !, { and ( ), every multi-line substitution closed by "||" (M);
  exceptions only via its ALLOW table (file~rule~text~category; the text must occur in the
  offending line; --check-allow turns a stale entry into a hit). Limit: a pipeline
  at a function's tail consumed by the caller is not seen.

10. Accepted bounded-pilot limitations (d11; carried from d9, per Reviewer D4-D8)
  - Path check/use and report check/open races by the same uid or root (no pinning).
  - ACL content not evaluated; an ACL the OS fails to read may list as none.
  - Report parent privacy (0700) recommended, not enforced; session.conf 0644 recommended.
  - One apply path disabled (admin-session; d17: the FileVault key writer is module 6, sec 13e; shared copy is enabled in d15, module 4, sec 13b; apps install in d16, module 5, sec 13c); the first-login LaunchAgent installer (module 3) is enabled in d14, see sec 13a; FileVault key saving is a manual
    runbook step only when module 6 is not configured or FileVault is already on; manual/pending statuses cannot be turned into verified acceptance.
  - Harness privacy scanner detects ACCIDENTAL leaks only; same-uid malicious code is
    contained by the test runner's sandbox, not the scanner.
  - All evidence is synthetic fixtures; nothing is validated on a Mac.
  - Not routed through the scalar readers (not reported facts): bootstrap/platform switch
    "uname -s" (fixture refusal also keys on CoreServices and root) and the Darwin/stat
    selector. Multi-line tool outputs (lists, prefs) keep their own per-consumer grammar.
  - Salt clearing runs after bootstrap's first native uname; an inherited, discarded
    WSP_* value may be visible to that one process. No generated salt is exposed.
  - Capture limits: head/tee/od/wc are trusted stock tools - one that exits 0 while
    consistently lying (same short output to every copy) is not detectable; the
    decoder (Bash builtin printf) cannot be fault-injected, so its length check is
    exercised only on success paths. Memory per capture ~ several x 1 MiB at most.
  - Direct, unencoded reads remain only where the static check's ALLOW table lists
    them: bootstrap trust (ls/stat/id/pwd/uname -s, before the library), filesystem
    trust helpers (stat owner/mode, ACL listing), hashes/random-id provenance labels,
    report header labels, unused checkpoint helpers. The random salt is checked (32 hex)
    or the run refuses. The awk validator itself is a trusted stock tool: one that exits
    0 with a fully self-consistent wrong result is not detectable (faults that break
    status, length or the end marker are).
  - Scrub check (d10): the line-exemption token is honoured ONLY in the one file named in
    EXEMPT_FILES in the check itself (the check, for its own rule text; the harness builds its samples at
    run time and carries no token); in any other file it is a
    HIT (exempt-token-misuse) and the line is scanned normally. The summary prints exempt=N and
    --expect-exempt N turns a different count into a HIT (the harness pins N).
    Patterns are checked as grep -E (GNU/BSD differences in exotic ERE are not modelled).
  - Harness scanner: find/readlink/hash traversal errors and unreadable directories are
    not hits; declared-link target content is not re-verified; literal canaries only.

11. Public-repo scrub (d11) - no employer or site value in code, tests or doc defaults
  Everything site-specific lives in operator config (computer-name templates, account
  names, shared items, APP_LIST) with generic examples only: example.com/.org/.net and
  subdomains, *.test, *.invalid, RFC 5737 (192.0.2.x, 198.51.100.x, 203.0.113.x),
  10.0.0.x, 127.x. No personal or noreply address and no vendor product name belongs in
  any file; commit metadata is handled by the release step.
  workstationadmin-scrub-check.txt DIR [--site-file FILE | --generic-only] [--strict-docs] [--expect-exempt N]:
    site patterns (one ERE per line, # comments) come from a local file OUTSIDE the suite
    directory (a file inside it, or a missing/empty one, exits 3: fail closed);
    every pattern is validated as an ERE at load: an invalid one -> exit 3, named by its
    number only; (d10) a pattern with a leading or trailing blank, tab or BOM -> exit 3; a grep status above 1 or any awk failure -> exit 3 (never a false clean);
    CRLF pattern and scanned files are normalised;
    built-in rules: IP outside the allowed ranges (IP), e-mail incl. any noreply address
    (MAIL), URL/www hostnames outside the allowed domains (HOST), vendor product words
    (VEND); file names are matched too. A line carrying the exemption token is exempt only
    in the one allowlisted file (see sec 10); the summary prints exempt=N.
    DIR is traversed recursively INCLUDING dotfiles and hidden directories; symlinks,
    special files and .git entries are hits (scan an export, not a repository).
    Output is file:line plus the rule or pattern number only; matched text is never printed.
    (d10) A site-pattern hit on a FILE NAME prints "entry#K name pattern#N" and later hits in
    that file use entry#K, so the path (which may be the sensitive text) is never printed.
    Exit 0 clean, 1 hits, 3 setup. documentation-*.txt findings print as DOCHIT (reported,
    exit 0) because the documentation owner owns them. RELEASE MODE: --site-file FILE --strict-docs (a DOCHIT then
    exits 1); never --generic-only. --generic-only labels itself and is what the harness
    runs (the site file does not exist in the sandbox); the harness also runs synthetic
    positive and negative self-tests of the scrub check and of the static check.
  The suite operator-account convention WSP_OPERATOR="workstationadmin" is also the file
  name prefix; it is a generic convention, not an employer value. Open decision for the
  owner: keep it or make it a documented single-edit constant before publication.

12. Software updates writer (d11, requirement R16; R17 gatekeeper and R20 checks unchanged)
  Module: workstationadmin-mod-updates.txt. Apple-supported methods only: defaults write
  (as root, after the apply gate) on /Library/Preferences/com.apple.SoftwareUpdate and
  /Library/Preferences/com.apple.commerce, and read-only softwareupdate --schedule. No
  install, no restart, no softwareupdate install/download/schedule-change verb, no Apple Account
  or paid action anywhere in the module (the harness greps the production text for these).
  Keys and policy (operator policy.conf; NO default, unset -> BLOCKED_POLICY). OWNER DECISION (d11,
  owner, reviewer B2): the five security-update settings ALWAYS stay on, so each accepts ONLY "on";
  "off" -> BLOCKED_POLICY "R16 keeps this setting on", zero writes, no backup. UPDATES_MACOS_INSTALL
  accepts ONLY "off". There is no operator-chosen "off" (none is built):
    com.apple.SoftwareUpdate AutomaticCheckEnabled            UPDATES_AUTO_CHECK      (on only)
    com.apple.SoftwareUpdate AutomaticDownload                UPDATES_AUTO_DOWNLOAD   (on only)
    com.apple.SoftwareUpdate ConfigDataInstall                UPDATES_CONFIG_DATA     (on only)
    com.apple.SoftwareUpdate CriticalUpdateInstall            UPDATES_CRITICAL        (on only)
    com.apple.SoftwareUpdate AutomaticallyInstallMacOSUpdates UPDATES_MACOS_INSTALL   (off only; the
        report's check label is AutoInstallOSUpdates - same setting, shorter name because a 32-character
        key would be shown as an opaque token)
    com.apple.commerce       AutoUpdate                       UPDATES_APP_STORE       (on only; App Store apps;
        the App Store authorization itself stays P09/PENDING_LOGIN elsewhere)
  A malformed value (anything but on/off, case-sensitive) -> BLOCKED_POLICY, value not echoed.
  Flow per key: typed read (wsp_pref_read: on/off only for exit 0, one line, value exactly 1 or 0;
  "unset" only for exit 1 with empty stdout and the not-found class; everything else unknown ->
  UNKNOWN) -> management check (wsp_profile_state, below; managed -> BLOCKED_POLICY "reported, never
  overridden"; unknown -> UNKNOWN) -> equal: ALREADY_CORRECT; inspect/dry-run: PROPOSED with zero
  writes -> apply: ONE verified backup per preference file (below), an identity re-check right before
  the first write to it, then defaults write -bool, then the typed read-back; equal ->
  CHANGED_VERIFIED, otherwise FAILED (a write that does nothing or a reader that lies is FAILED,
  never CHANGED_VERIFIED). AutomaticCheckEnabled is also cross-checked with the read-only
  softwareupdate --schedule reader (agree -> effective-cli evidence; unreadable -> UNKNOWN;
  disagree -> FAILED). Re-apply -> ALREADY_CORRECT and no new backup or write. verify mode
  reports a remaining difference as FAILED.
  APPLY GATE IS NOT CONSENT (test note, d11): wsp_apply_gate is a non-interactive prerequisite/policy
  check (macOS, started by the operator account through sudo, console/identity context, TARGET_OS_MAJOR
  and ALLOWED_BUILDS policy, prerequisites). It asks nothing and needs no TTY; passing it is not a
  confirmation by a person. The updates module never calls wsp_confirm (the harness checks the module
  text). The only interactive confirmation in the suite is the driver's (workstationadmin-provision.txt,
  apply mode, token APPLY); running the updates module on its own in apply mode has no prompt.
  Management state (wsp_profile_state, d11, reviewer B3): MANAGED when any line of
  "profiles show -type configuration" names com.apple.SoftwareUpdate, com.apple.commerce,
  com.apple.appstore, com.apple.applicationaccess or com.apple.ManagedClient (identifier or payload
  type), or when "profiles status -type enrollment" reads "MDM enrollment: Yes" (this also covers
  Declarative Device Management, which the profile listing cannot show). NONE only when the listing
  is exactly "There are no configuration profiles installed" (optionally "... in the system domain")
  AND the enrollment reads "MDM enrollment: No". Everything else (tool failure, unreadable
  enrollment, unrecognised output, a listing with only unrelated profiles we cannot classify) is
  UNKNOWN and nothing is written. So a Mac with unrelated profiles reports UNKNOWN for these
  settings in this draft (conservative; a later draft could classify known-harmless payload types).
  Backup (wsp_backup, d11, reviewer B1): a symlink (including a dangling one) is refused FIRST;
  anything that exists but is not a regular file (directory, FIFO, device) is refused; a missing
  plist gets an explicit "<name>.ABSENT" marker; the copy is made with cp -p and must compare equal
  to the source (cmp) or the backup fails; every backup directory is unique (mktemp -d under
  <base>/backup, mode 700), so two runs in the same second keep both pristine copies;
  wsp_backup_check re-compares the source with the backup right before the first write and refuses
  if anything changed. A refused or failed backup -> that plist's keys are FAILED and nothing is
  written to it (the other plist is unaffected). The report names the backup directory (d12: the FULL
  path in the optional trailing record field backup=, the last component in the detail of each written key;
  see sec 13 for the path field class). ROLLBACK IS MANUAL (record rollback-manual,
  PENDING_CONSENT): as root, copy <backup dir>/<plist name> back over the plist (or delete the plist
  if an ABSENT marker is there); nothing restores automatically.
  Fixed records: management-overrides (ALREADY_CORRECT none / BLOCKED_POLICY managed / UNKNOWN),
  effective-settings-view PENDING_LOGIN (confirm in System Settings, General, Software Update),
  update-install PENDING_CONSENT (nothing is installed or restarted; R16 is not install
  authorization), rollback-manual PENDING_CONSENT. A separate policy flag plus confirmation for
  installing/restarting is NOT implemented; it needs its own review.
  To confirm on a Mac (not validated; list for the validation plan): (1) the exact grammar of
  "profiles show -type configuration" - the empty-listing sentence(s), the per-payload "payload[N]
  type = ..." lines, how many lines a profile prints and whether device-level and user-level
